# Проверка TourCraft
Дата проверки — 21.11.2026. Windows, .NET SDK 10.0.401, SQL Server 2022 Express LocalDB. Проверены команды приложения через его класс доступа к данным в отдельной временной базе из штатных скриптов. Снимки экранов получены при открытии настоящих WPF-форм с учебной базой.

| ID | Начальные условия и действия | Ожидаемый результат | Фактический результат |
| --- | --- | --- | --- |
| TC-01 | На пустом экземпляре создать учебную базу, выполнить schema.sql и seed.sql, открыть каталог | Два маршрута | Пройдено — каталог вернул две записи |
| TC-02 | Добавить тестовый маршрут, найти его по названию, изменить название | Поиск по новому названию возвращает исходный ID | Пройдено — ID совпал |
| TC-03 | Удалить созданный маршрут без отправлений, повторить поиск | Пустая выборка | Пройдено — 0 строк |
| TC-04 | На начальных данных найти маршруты по направлению «Байкал» и включить фильтр открытых отправлений | Один маршрут и два открытых отправления | Пройдено — обе выборки совпали |
| TC-05 | Построить отчёты после начального наполнения | Популярное направление имеет 2 забронированных места, загрузка соответствующего отправления составляет 16,7% | Пройдено — 2 места и 16,7% |
| TC-06 | На открытом отправлении забронировать место, записать 123,45 ₽, отменить бронь дважды | Остаток уменьшится на 1, платёж появится в истории, первая отмена вернёт место, вторая будет отклонена | Пройдено — сумма и оба изменения остатка проверены |
| TC-07 | Запросить больше свободного остатка, затем забронировать при закрытом наборе. Открыть набор и одновременно отправить две заявки на весь остаток | Первые две попытки отклонены без изменения остатка. В конкурентной паре успешна ровно одна заявка | Пройдено — один победитель, остаток 0 |
| TC-08 | На открытом отправлении передать в операцию брони несуществующий ID клиента. Ошибка внешнего ключа возникает после изменения остатка | Транзакция откатится, остаток и число броней останутся прежними | Пройдено — оба значения проверены |

## Замечания по проверке
В процессе проверки исправлены ограничение целостности вместимости в SQL-схеме и выборка каталога при пустом поиске. Повторный прогон прошёл успешно.
